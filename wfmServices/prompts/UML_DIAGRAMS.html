📊 Class Diagram - Core Entities

This diagram shows the main data entities and their relationships in the WFM system.

📊 Core Entities Overview

👤 User

Key Attributes: id, username, email, tenant_id, status

Methods: authenticate(), has_permission()

Relationships: Has roles, Creates jobs, Reports issues

🎭 Role

Key Attributes: id, name, description, tenant_id, status

Purpose: Defines user permissions and access levels

💼 Job

Key Attributes: id, title, description, priority, status, assigned_analyst_id

Methods: schedule(), assign_analyst()

Relationships: Assigned to analyst, Related to issues

👨‍💼 Analyst

Key Attributes: id, name, email, experience_years, max_jobs

Methods: is_available(), get_workload()

Relationships: Assigned to jobs

🐛 Issue

Key Attributes: id, title, description, priority, category, job_id

Methods: escalate(), add_comment()

Relationships: Related to jobs

⚖️ Rule

Key Attributes: id, name, description, tag_name, sequence

Methods: evaluate(), execute_actions()

Purpose: Business logic and automation

⚙️ Configuration

Key Attributes: id, key, description, category

Methods: validate(), get_value()

Purpose: System configuration management

📈 Report

Key Attributes: id, name, report_type, status

Methods: generate(), export()

Purpose: Analytics and reporting

🔗 Key Relationships

  • User → Role: Users have roles for access control
  • User → Job: Users create and manage jobs
  • User → Issue: Users report and track issues
  • Analyst → Job: Analysts are assigned to jobs
  • Job → Issue: Jobs can have related issues
  • Rule → Job: Rules affect job processing
  • Configuration → Job: Configurations control job behavior
  • Report → Job/Issue: Reports analyze job and issue data
